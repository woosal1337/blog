# Check a new conversation

Run this exercise in a copy of `workspace/`. Keep this file outside the folder where the agent works. Folder scope alone is not a sandbox.

## Read the current record

Start a new session with the normal project instructions and permitted file access. Ask:

> Resume Lantern. What is the accepted decision for the review, who owns the review, and what remains unresolved? Link the records that support your answer.

Open the cited passages yourself. Check the record date and the link to the current decision. A correct answer without a valid source needs review.

## Apply a new correction

1. In the copy, add a dated source that explicitly accepts violet as the new prototype color. Mark it as fictional.
2. Ask the agent to propose the corresponding decision and task changes.
3. Review and apply the change. Preserve the earlier decisions and source transcripts.
4. End the session. Start another with the same access and ask the original resume question.
5. Compare its answer with the records. Check the source, owner, unknown deadline, and publication status.

Do not mention violet in the second question. Keep approval for the color separate from approval to publish.

## Expected state before your change

The current example uses amber. Mira owns the review. Its deadline is unknown, and publication is not approved. Blue remains in the history. Read the later meeting at 00:08, 00:24, 00:32, and 00:45.

After your accepted correction, check that the color is violet. Other fields change only if your new source explicitly changes them.

## Record a failure

Write the question, answer, cited source, and expected value in a separate check note. Say whether the file existed, access worked, and the current decision was discoverable. Do not report a success rate from one exercise.
