## Error Response

```json
{
  "error": {
    "code": "rate_limit_exceeded",
    "message": "You've exceeded the rate limit of 100 requests per minute. Please wait and try again shortly.",
    "retry_after": 42
  }
}
```

**HTTP Status:** `429 Too Many Requests`
**Header:** `Retry-After: 42` (seconds until you can retry)

## User-Facing Message

> **Rate limit exceeded**
> You've made too many requests in a short period. Our limit is 100 requests per minute per API key. Please wait 42 seconds before trying again.

## Explanation

This limit protects the API from overload and ensures fair access for all users. It resets on a rolling basis, so requests will succeed again shortly after older ones age out of the current window.

**To avoid this in the future:**
- Add exponential backoff and retry logic using the `Retry-After` header.
- Batch requests where possible instead of firing them individually.
- Cache responses for data that doesn't change frequently.
- If you consistently need a higher limit, contact support to discuss a plan upgrade.
